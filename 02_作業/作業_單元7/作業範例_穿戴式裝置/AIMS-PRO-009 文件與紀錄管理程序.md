## 1. 目的

確保智腕科技 AIMS 所需的文件化資訊（documented information）：

1. **可識別**：看到一份文件，就知道它是什麼、哪一版、誰核准、何時生效；
2. **可取得、正確**：需要的人在需要時取得現行版，不會誤用舊版；
3. **受保護**：機密性、完整性、可用性不被破壞，未經授權不能修改；
4. **能當證據**：紀錄能追溯到產生它的程序、人員與時間，保存到期限屆滿再依規定處置。

講師強調的判準：**「文件管制形式完整」不等於「文件在實際工作中可取得、正確、受保護、能當有效證據」**。本程序 §15 的績效指標與抽查，就是用來驗證後者。

## 2. 適用範圍

| 類別 | 包含 |
|---|---|
| 內部文件（維持，maintain） | 手冊（MAN）、政策（POL）、程序書（PRO）、作業指導書（SOP）、表單空白格式（FRM）、清冊（REG）、適用性聲明（SOA）、矩陣（MTX） |
| 紀錄（保存，retain） | 填寫後的表單、評鑑與審查報告、會議紀錄、訓練紀錄、測試報告、事件與日誌、核准紀錄 |
| AI 特有文件化資訊 | 模型卡與模型版本、資料集清冊與資料血緣、Prompt 與系統設定版本、事件日誌（§12） |
| 外來文件 | ISO/IEC 標準、法律與政府指引、客戶規範、供應商與第三方 AI 服務文件（含 DPA）、課程範本 |
| 媒體 | 電子檔（主要）、紙本（簽核正本、外部來函） |

**不適用**：個人工作筆記、未進入審查流程的草稿（但草稿不得被當作現行文件使用或對外提供）。

## 4. 名詞定義

| 名詞 | 本公司用法 |
|---|---|
| 文件（document） | 規定「應該怎麼做」的資訊，需 **維持** 為最新；會改版 |
| 紀錄（record） | 證明「已經做了什麼」的資訊，需 **保存**；原則上不改，更正須留痕 |
| 受控文件 | 已核准、登錄於文件總清冊、發布於電子文件管理系統（DMS）的文件 |
| 參考用副本 | 從 DMS 下載或列印的副本，標示「參考用，以 DMS 為準」，不受版本追蹤 |
| 外來文件 | 非本公司制定，但為 AIMS 規劃與運作所需的文件 |
| 文件擁有人 | 負責撰寫、維護、定期審查某文件的人 |
| 母程序 | 表單所屬的程序書，決定表單編號 |

## 6. 文件類型與編號規則（42001 §7.5.2 a）

### 6.1 類型代碼與文件層級

| 層級 | 類型 | 代碼 | 編號格式 | 範例 |
|---|---|---|---|---|
| 1 | 手冊 | MAN | AIMS-MAN-NNN | AIMS-MAN-001 AI治理手冊 |
| 1 | 政策 | POL | AIMS-POL-NNN | AIMS-POL-001 AI政策 |
| 2 | 程序書 | PRO | AIMS-PRO-NNN（依附件 B 總表） | AIMS-PRO-002 AI風險管理程序 |
| 3 | 作業指導書 | SOP | AIMS-SOP-NNN-SS（NNN = 母程序） | AIMS-SOP-009-01 DMS 操作說明 |
| 3 | 表單 | FRM | **AIMS-FRM-NNN-SS（NNN = 母程序號，SS = 流水號）** | AIMS-FRM-002-01 AI風險評鑑暨登錄表 |
| 3 | 清冊／聲明／矩陣 | REG／SOA／MTX | AIMS-XXX-NNN | AIMS-REG-001 AI法規遵循清冊、AIMS-SOA-001 |
| 4 | 紀錄 | — | **〈前綴〉-YYYY-NNN**（年度流水號） | AIA-2026-001、AIGC-2026-03、HR-2026-031 |

### 6.2 編號原則

1. **表單跟著母程序編號**。表單的 NNN 必須等於負責產生該紀錄之程序書的編號；查到表單即可知道依哪份程序執行。
2. **程序號依附件 B 總表分配**，總表由 AIMS 管理代表維護；新增程序先登錄總表再撰寫。
3. **作廢或改號後的編號不重用**，在總清冊標註「停用，原用途：…」，避免舊紀錄與新文件混淆。
4. 紀錄前綴由母程序定義並登錄於附件 C 紀錄清冊（如 AIA＝衝擊評鑑報告、AIGC＝AI 治理委員會會議紀錄）。
5. 檔名格式：`〈文件編號〉 〈文件名稱〉_v〈版本〉`；DMS 上以文件編號為唯一鍵。

## 7. 資訊分級（42001 §7.5.3 b；與 POL-002 一致）

| 等級 | 定義 | 範例 | 處理規則 |
|---|---|---|---|
| 公開 | 可對外發布 | AI 政策、資安政策、AI 透明度摘要 | 發布前經 AIMS 管理代表與法務確認 |
| 內部使用 | 僅限員工與受保密約束之合作方 | 程序書、範圍界定表、風險登錄表 | DMS 全員唯讀；對外提供須核准 |
| 機密 | 外洩會造成重大損害或含個資 | AIA 報告全文、DPIA、模型與資料集細節、含使用者資料之紀錄 | 依「需要知道」授權；加密存放；下載與列印留日誌；不得輸入外部生成式 AI |
| 極機密 | 外洩會造成嚴重法律或安全後果 | 大量健康資料原始檔、加密金鑰、資安事件鑑識資料 | 個別授權＋主管核准；不得離開指定系統 |

表頭「資訊分級」欄必填；同一文件有對外版時，另立文件並標註「對外版」（例：AIA-2026-001 對外 AI 透明度摘要）。

## 9. 變更管制（42001 §7.5.3 c）

### 9.1 變更分類

| 類別 | 定義 | 範例 | 核准 | 版本 |
|---|---|---|---|---|
| 重大 | 改變要求、流程、權責、風險準則、門檻、適用範圍 | 修改風險等級門檻；新增衝擊評鑑觸發條件 | 依 §8.3 原核准層級 | 主版號 +1（1.x → 2.0） |
| 一般 | 不改變要求，但新增參考、範例、說明或附件內容 | 新增參考文件；附件風險登錄表摘錄更新 | AIMS 管理代表 | 次版號 +1（1.0 → 1.1） |
| 編修 | 錯字、格式、交叉引用編號修正 | 表單改號後更新引用 | 文件擁有人＋AIMS 管理代表確認 | 次版號 +1 |

### 9.2 變更流程

```
變更申請（FRM-009-03）→ 影響分析（有哪些文件引用它？是否影響紀錄格式？是否需訓練？）
  → 修訂並更新修訂紀錄 → 依類別審查核准 → DMS 發布新版、舊版移入歷史區並標示「作廢」
  → 更新文件總清冊 → 通知使用者（必要時訓練）→ 同步修正引用文件的交叉引用
```

**禁止**：核准後直接修改內容而不升版；在同一版本號下存在兩種內容。

### 9.3 交叉引用一致性

文件擁有人在每次變更時，須以文件編號全文搜尋 DMS，確認：(a) 引用本文件的其他文件仍正確；(b) 本文件引用的文件 **存在且為現行版**；不存在者須在總清冊登錄為「規劃中」並列負責人與期限（§11）。

## 10. 發布、取用與保護（42001 §7.5.3 a、b）

### 10.1 發布與取用

| 項目 | 規定 |
|---|---|
| 唯一正本 | DMS 上的 PDF 發布版；可編輯原始檔存於 DMS 草稿區，僅文件擁有人可寫 |
| 取用 | 全員可於 DMS 搜尋現行版（依分級權限）；產線與客服另於工作系統內嵌連結，避免使用本機舊檔 |
| 紙本 | 僅限簽核正本與現場必要張貼；張貼版須蓋「受控」章並登錄發放位置，改版時回收 |
| 對外提供 | 依 §7 分級；機密以上須核准並留提供紀錄 |

### 10.2 保護

| 威脅 | 控制 |
|---|---|
| 未授權修改 | DMS 角色權限；發布版唯讀；所有變更有稽核日誌 |
| 遺失 | 每日備份、異地備份；每季還原測試（資訊安全部） |
| 外洩 | 機密以上加密；下載浮水印；離職即停權 |
| 無法讀取 | 長期保存紀錄以 PDF/A 存檔；系統汰換前完成資料轉移與可讀性驗證 |
| 證據竄改 | 稽核用重要紀錄（核准、測試報告、AIA）發布時計算雜湊值並登錄 |

### 10.3 紀錄的更正

紀錄不得覆寫。更正時保留原內容、註明更正內容、原因、更正人與日期（電子紀錄以新版本保存，舊版本保留）。

### 10.4 使用生成式 AI 撰寫文件

1. 可使用公司核准的企業版生成式 AI 工具（合約不留存、不訓練）協助撰寫草稿；**機密以上資訊不得輸入**（參照行政院生成式 AI 參考指引第四點；RC-010）。
2. AI 產出必須由文件擁有人逐項查證（條款編號、法規條號、數據、交叉引用），審查人不得只審 AI 摘要。
3. 修訂紀錄的「內容」欄註明「AI 輔助撰寫，已人工查證」，以利稽核追溯。

## 11. 文件總清冊與外來文件管理（42001 §7.5.3 最後一段）

### 11.1 文件總清冊（FRM-009-01）

每份文件一列：文件編號、名稱、類型、分級、版本、生效日、文件擁有人、核准者、下次審查日、狀態、存放位置。狀態分為：

| 狀態 | 意義 |
|---|---|
| 現行 | 已核准、已發布 |
| 規劃中 | 已分配編號、已被其他文件引用，但尚未建立；**須有負責人與期限** |
| 嵌入 | 格式暫以其他文件附件呈現（例：SOA 摘錄在 PRO-002 附件 B），須註明位置與何時獨立 |
| 停用 | 編號停止使用，不得重用 |
| 作廢 | 已被新版取代，存於歷史區 |

### 11.2 外來文件清冊（FRM-009-04）

| 規定 | 內容 |
|---|---|
| 登錄 | 名稱、版本或發布日、來源、取得日、管理人、引用本文件的內部文件 |
| 版本監控 | 標準：AIMS 管理代表每年查 ISO 網站；法規與政府指引：林法務每季查核（與 REG-001 一致） |
| 授權 | ISO 標準依購買授權使用，不得轉貼或上傳外部；政府公開資訊可保存原文 |
| 更新影響 | 外來文件改版時，評估引用它的內部文件是否需變更（走 §9） |

## 13. 保存期限與處置（42001 §7.5.3 d）

### 13.1 保存期限（FRM-009-02 紀錄保存清冊摘要）

| 紀錄 | 期限 | 起算點 | 理由 |
|---|---|---|---|
| 政策、程序等文件的作廢版本 | 5 年 | 作廢日 | 追溯當時有效的要求 |

### 13.2 處置

1. 到期前 30 日，DMS 自動通知紀錄擁有人；擁有人確認無 **法律保全**（訴訟、調查、主管機關要求）後提出銷毀申請（FRM-009-05）。

3. 有法律保全者暫停銷毀，由林法務決定解除時點。
