## 一、核心理念

**「保護使用者健康資料，人人有責；安全可信，才是好產品。」**

本公司視資訊安全與個人資料保護為 AI 產品的基礎。使用者的生理資料與手機連動資料一旦外洩，將無法挽回，因此本公司以最高標準保護。

## 二、資訊安全承諾

本公司承諾：

- 確保資訊資產之**機密性、完整性與可用性**，涵蓋使用者生理資料、個人資料、AI 模型及公司營業秘密。
- 持續監控並有效回應資安威脅與事故，降低對使用者及營運之衝擊。
- 落實全體員工之資安責任，強化資安意識。
- 將資安要求延伸至供應商與 AI 技術供應商。
- 遵循個人資料保護法、GDPR 等法規，並參照資通安全管理法之要求建立管理機制。

## 三、治理架構

| 層級 | 職責 |
|---|---|
| 董事會 | 核定本政策；每年聽取資安與個資保護報告 |
| AI治理委員會（兼資訊安全委員會，主席：總經理） | 審議資安與 AI 政策、重大風險與事故；每季開會 |
| 資訊安全長（CISO，由資訊安全部經理兼任，總經理任命） | 統籌資安與個資保護；重大事故對外通報 |
| 資訊安全部 | 執行防護、監控、弱點管理、DPIA 審查 |
| 各部門主管 | 落實部門內資安要求 |

> 本公司非資通安全管理法之特定非公務機關，仍參照該法設置資訊安全長及資安專職人員，作為良好實務。

## 四、AI 系統安全要求

| 項目 | 要求 |
|---|---|
| 安全開發（SDLC） | AI 系統於起始階段即納入資安與隱私需求（作業 4 FRM-010-02）；上線前進行程式碼檢視、弱點掃描、滲透測試 |
| 模型與 Prompt 安全 | 模型與系統 Prompt 納入版本控管；語音助理進行紅隊測試，防止 Prompt Injection 與不當回答 |
| 存取控制 | 最小權限原則；生產環境與健康資料存取須多因子驗證並留存日誌 |
| 加密 | 藍牙傳輸加密；手機至雲端 TLS 1.2 以上；雲端儲存 AES-256 |
| 變更管理 | 模型更新視為變更，須經測試與核准後部署 |

## 五、個人資料保護

| 原則 | 做法 |
|---|---|
| 從嚴分級 | 心率、血氧、睡眠等健康相關資料比照**特種個資**保護 |
| 告知與同意 | 依個資法履行告知；健康資料分析、模型訓練、手機連動各項**分別取得同意**，預設關閉 |
| 最小化 | 行事曆僅讀取忙碌／空閒；通知內容僅在裝置端顯示；不讀取聯絡人 |
| 目的限制 | 僅用於使用者同意之健康服務，不用於廣告、保險或第三方行銷 |
| 當事人權利 | App 內提供查詢、更正、撤回同意、刪除；刪除請求 30 日內完成 |
| 跨境傳輸 | 歐盟使用者資料依 GDPR 傳輸機制處理 |
| 委外監督 | 雲端與 AI 供應商簽署資料處理協議，本公司依個資法對受託者負監督責任 |

## 六、資安事件管理與通報

| 步驟 | 要求 |
|---|---|
| 偵測與通報 | 員工發現疑似事件應立即通報資訊安全部 |
| 分級 | 涉及健康資料或大量個資外洩列為**重大事件** |
| 對內通報 | 重大事件 1 小時內通報資訊安全長，24 小時內報告總經理 |
| 對外通報 | 個資外洩依個資法通知當事人；歐盟使用者依 GDPR 於 72 小時內通報監管機關；涉及政府委外案件依契約及資通安全管理法要求時限通報 |
| 復原與檢討 | 事件結案須完成根因分析與矯正措施 |

## 七、營運持續

建立營運持續計畫（BCP）與災難復原（DR）機制，雲端服務與健康資料每日備份，每年至少演練一次。

## 八、績效指標

| 指標 | 目標 |
|---|---|
| 高風險弱點 30 日內修補率 | ≥ 95% |
| 重大事件 1 小時內通報率 | 100% |
| 年度資安與個資訓練完成率 | ≥ 95% |
| 重大個資事故 | 0 件 |

指標每季於 AI 治理委員會檢討，每年納入管理審查。
