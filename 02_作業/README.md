## 新增一個單元作業

```
02_作業/作業_單元N/
├── 作業_N_<主題>.md             ← 題目、條件、參考（已建立空白檔）
├── 參考文件格式/                 ← 課程或自己整理的空白範本（選用）
└── 作業範例_穿戴式裝置/
    ├── 00_README_文件清單與條款對應.md   ← 文件清單 + 條款對應矩陣
    └── AIMS-XXX-NNN-NN <文件名>.md
```

## 案例公司

所有作業延續同一家虛構公司「智腕科技」（AI 智慧手錶），情境設定、已用編號、文件編號規則與各單元產出見 **[案例公司_穿戴式裝置.md](案例公司_穿戴式裝置.md)**。

> 課程平台的「提交作業」頁沒有題目，只有繳交規則；題目＝各單元「小組輸出」，見 `00_課程導覽/單元重點/`。

### 文件編號規則（沿用課程範本）

| 類型 | 前綴 | 例 |
|---|---|---|
| 手冊 | AIMS-MAN | AIMS-MAN-001 AI 治理手冊 |
| 政策 | AIMS-POL | AIMS-POL-001 AI 政策 |
| 程序 | AIMS-PRO | AIMS-PRO-001 組織情境管理程序 |
| 表單 | AIMS-FRM-<程序號>-<序號> | AIMS-FRM-001-02 利害關係人需求分析表 |

## 寫作業的自我檢查（講師評分精神）

- [ ] 每項主張都有 **編號**，且被下游文件引用（可追溯）
- [ ] 每個要求都有 **驗證方式**（測試、紀錄、量測）
- [ ] 有 **負責人、核准、版本、日期、審查週期／觸發條件**
- [ ] 有 **條款對應矩陣**（00_README）讓稽核員一眼找到證據
- [ ] 範圍與排除有理由，且與資料流、供應商依存一致
- [ ] 用稽核員角度自問：這份文件能回答「誰、依什麼、證據在哪」嗎？
