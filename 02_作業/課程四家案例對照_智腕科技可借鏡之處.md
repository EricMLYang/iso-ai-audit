# 課程四家案例 vs 智腕科技：可借鏡之處

> 對應課程資源：課程參引「案例研討」的四家案例公司（智慧運輸、生命醫學、居家人形機器人、環境永續）。
> 依 [使用原則](../00_課程導覽/使用原則.md)，**課程案例原文不放進本 repo**。本檔只用自己的話歸納四家案例的 **共通設計模式**，再拿來檢視智腕科技還缺什麼。**不修改既有作業**，只列出後續單元可參考的方向。

## 1. 四家案例的共同骨架

課程的案例包都是「**一家公司、多套管理系統共用情境**」，每家都有：

| 區塊 | 內容型態 |
|---|---|
| 文件管制資訊 | 案例包本身也有編號、版次、核准者、上階文件 |
| 使用規則與角色切換 | **單元 1～8 當導入者，單元 9 以後當稽核員**，互相稽核其他小組的產出 |
| 公司基本資料 | 據點與人數、產品平台、服務、客戶、關注方需求 |
| 外部議題 | 國際競爭、**地緣政治**、**戰爭與衝突**、區域市場、本地營運、**氣候變遷**，每項都寫「對管理系統的關聯」 |
| 適用法規與合約 | 清單 |
| 關注方需求及期望 | 每個關注方都寫：需求、**轉成什麼管理系統依據**、建議連結哪些文件、**建議 Owner** |
| 組織單位與人數 | 用來寫 RACI 與範圍 |
| 文字式組織架構圖 | 依 **三道防線** 排列：第一線流程 Owner、第二線治理監督、第三線獨立保證（內部稽核） |
| 角色任命建議 | 每個角色寫建議職稱、**應保留證據**、RACI 提示 |
| 關鍵流程、系統、資訊資產與 Owner | — |
| 供應鏈與外包 | 具名供應商與其接觸的資料 |
| 主要風險與 **可量測目標** | 目標都有數字與時限，例如「72 小時內」「完成率 100%」 |
| RACI 起始矩陣 | 規則：**每項活動至少一個 A**；**內部稽核不得稽核自身流程** |
| 各標準專屬情境 | AIMS、PIMS、BCMS、ITSM、QMS 各五個主題 |

## 2. 四家案例的 AIMS 情境：共通的五個主題

四家公司的 AIMS 情境需求都圍繞同樣五個主題，只是換成各自產業的話：

| 主題 | 共通要求（自己的話） | 典型證據 |
|---|---|---|
| **AI 系統與使用目的** | 界定 AI 系統邊界、預期用途、**禁用情境或不得取代專業判斷的邊界**、人工覆核點 | AI 系統清冊、用途限制聲明、人工覆核規則 |
| **資料與偏差** | 資料來源、標註品質、代表性、漂移、**測試集隔離**、版本、再訓練觸發條件 | 資料集清冊、標註規範、偏差測試、漂移監控紀錄 |
| **安全與人機互動或可解釋性** | 誤判對人身、權益或決策的影響；要能說明依據 | 安全測試、模擬驗證、模型說明文件、決策紀錄 |
| **AI 供應鏈** | 標註商、雲端 GPU、模型服務、感測器供應商、共同研發方會接觸資料或模型權重 | 供應商評估、資料處理與智財條款、交付驗收 |
| **監督與改善** | 追蹤準確率、**誤報與漏報**、人工接手事件、投訴、模型更新後表現 | AI KPI／KRI、異常案例回饋、管理審查輸入 |

## 3. 拿來檢視智腕科技（後續單元的待辦方向）

| 案例包有的設計 | 智腕科技現況 | 建議在哪個單元補 |
|---|---|---|
| 外部議題含 **地緣政治、戰爭衝突** | 案例公司檔外部議題只有法規、市場、技術、環境 | 單元 4 已交；若之後改版，可補「感測器與晶片供應受出口管制影響」等議題 |
| 關注方需求寫 **建議 Owner** 與 **連結文件** | FRM-001-02 有需求與追溯 | 可在單元 8 運作軌跡中補 Owner 欄 |
| **三道防線** 組織架構 | 單元 5 有 RACI 與角色責任 | 單元 9 內部稽核作業可明寫內稽屬第三線、不得稽核自身流程 |
| 主要目標 **全部量化** | 單元 6 有 AI 目標管理表 FRM-003-01 | 單元 9 績效評估可沿用並補 KRI，例如漏報率 |
| AIMS 的 **禁用情境或用途邊界**，例如「不得取代醫療判斷」 | 衝擊評鑑 AIA-2026-001 有討論 | 單元 8 可把「不得作為醫療診斷」寫成使用者告知與 A.9 控制證據 |
| **誤報與漏報** 作為 KPI | 案例公司檔未明列 | 單元 9 監測量測計畫 |
| **人工接手事件** 紀錄 | 尚無 | 單元 8：健康預警的人工覆核流程 |
| **AI 供應商評估** 與資料智財條款 | 單元 6 風險有提到 | 單元 8：雲端推論與標註外包的供應商評估表 |
| **再訓練觸發條件** | 尚無 | 單元 8：對照 5338 的四個模型更新時機因素，見 [ISO5338 技術流程筆記](../01_核心觀念/課程資源筆記/ISO5338_技術流程逐項_稽核重點.md) §10 |
| 單元 9 以後 **互相稽核** | 單元 11～14 作業只有題目骨架 | 可用其他組的產出，或用本 repo 的智腕科技文件當受稽方練習 |

## 4. 跟智腕科技最像的是哪一家

**居家人形機器人** 那家最接近：同樣是 **居家場域、高齡或一般使用者、健康相關資料、裝置加雲端加 App、遠端更新**。可以參考它怎麼處理：
- 家屬、照護者與本人之間的 **授權邊界**。對應智腕科技「家人共享健康資料」功能。
- 跌倒偵測 **漏報** 的安全與法律責任。對應智腕科技的健康風險預警（AI-002）。
- **遠端更新失敗或回滾**。對應手錶韌體與模型 OTA。
- **維修退貨時清除資料**。對應手錶送修時的本機健康資料處理。
