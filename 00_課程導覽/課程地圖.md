# 課程地圖

5 天課程，核心標準：**ISO/IEC 42001**（AIMS 要求）、**ISO 19011**（稽核指引）、**ISO/IEC 17021-1**（驗證機構要求），並參考 **ISO/IEC 42006**（AIMS 驗證機構要求）、ISO/IEC 23894（AI 風險管理）、ISO/IEC 42005（AI 系統衝擊評鑑）、ISO/IEC 5338（AI 系統生命週期流程）、ISO/IEC 22989（AI 概念與詞彙）。

## 課程邏輯一句話

> **單元 4–10**：拿一家「已建好 AIMS」的案例公司，從 **內部稽核員** 角度做 **文件審查**（條款 4→10 逐條）。
> **單元 11–14**：把審查結果轉成 **驗證稽核**：稽核方案 → 規劃 → 現場稽核演練 → 報告與跟催。

每單元的共同節奏：講師說明 → 分組審查案例文件 → 用「第一階段文件審查稽核軌跡」工作文件寫稽核問題 → 討論「**文件存在** vs **文件能當可追溯、可驗證的稽核證據**」。

## 條款之間的「追溯主線」（每單元都會被問）

```
§4.1 內外部議題 ─┐
§4.2 關注方要求 ─┼─► §4.3 範圍 ─► §6.1 風險準則/評鑑/處理 ─► SoA（附錄A）─► §8 實作紀錄
                 │                      │                                      │
                 └──────────────► §5.2 AI 政策 ─► §6.2 AI 目標 ─► §9.1 量測 ─► §9.3 管理審查 ─► §10 改善
```

稽核時最常見的弱點：每一份文件單獨看都「存在」，但箭頭斷掉（例如：§4.2 列出的法規要求沒有出現在風險評鑑，或 SoA 排除某控制卻沒有理由）。
