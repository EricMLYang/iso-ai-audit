# ISO/IEC 42006:2025 — AIMS 驗證機構的附加要求（讀書筆記）

> 對應課程資源：課程參引〈ISO/IEC 42006, AIMS 稽核與驗證機構規範〉（單元 3、11、12；考試單元 2、3）。
> 自己的話整理。42006 是在 **17021-1 之上加的 AIMS 特定要求**；沒寫到的地方就「適用 17021-1」。17021-1 細節見 [ISO17021-1 筆記](ISO17021-1_驗證機構要求與驗證流程.md)。

## 0. 定位

- AIMS 驗證是 **第三方符合性評鑑**。
- 認證機構與同儕評估可以用 42006 評估驗證機構。
- **AIMS 證書不是產品證書**：要標示 AI 產品、流程、服務的符合性標誌，走的是 17065、17067、17030 那條路。AIMS 證書可在 17065 方案中使用以避免重複測試。

## 1. 公正性：比 17021-1 更嚴（§5.2）

驗證機構 **不得** 對其 42001 驗證客戶提供以下顧問：
1. **AIMS** 顧問
2. **資訊安全管理** 顧問
3. **個資保護** 顧問，例如擔任外部 DPO 或做資料保護檢查
4. **風險管理** 顧問

**可以做的事**：
- **公開** 訓練課程的講師，只講一般公開資訊。**不包括內訓或客戶專屬訓練**。
- 稽核前活動，**唯一目的** 是確認驗證對象、決定範圍、評估是否準備好接受稽核。

**不可以做的事**：
- 給特定企業顧問建議。
- 做本質上是稽核的工作，或導致最終驗證 **稽核時間被縮減** 的活動。
- 對 AIMS、AI 系統或 AI 流程提供 **特定解決方案或建議**。
- 替客戶做任何 **內部稽核**；**改名叫「檢查」或「評估」也不行**。

稽核或追查時 **指出改善機會但不提具體解法**，不算顧問。

## 2. 責任保障（§5.3）

要有 **保險或其他保障機制**，涵蓋人身傷害、財產損害、財務損失；保障金額要與 **客戶營業額** 相當。這不是產品責任，而是驗證過程不符要求造成的損害責任。

## 3. 能力要求（§7.1）

### 三種驗證職能要額外定義的知識

| 知識領域 | 申請審查與選派 | 報告審查與驗證決定 | 稽核與擔任組長 |
|---|---|---|---|
| AIMS 一般要求 | — | ✓ | ✓ |
| AIMS 標準、規範文件、驗證方案 | ✓ | ✓ | ✓ |
| AI 與 AIMS 相關 **法律義務** | ✓ | ✓ | ✓ |
| AI 術語、原則、實務、工具 | ✓ | ✓ | ✓ |
| 客戶產業領域 | ✓ | ✓ | ✓ |
| 客戶產品、流程、組織 | — | ✓ | ✓ |

**技術領域** 可依 AI 技術（電腦視覺、影像辨識、NLP、資料探勘）、應用領域（詐欺偵測、自駕、醫療、零售）或兩者組合定義。AIMS 驗證所需能力很多元，通常由 **多人組成能力群組（competent group）** 來涵蓋。

### 「每位成員」vs「團隊整體」— 考點

| 每位稽核員都要有 | 團隊整體具備即可 |
|---|---|
| AI、管理系統實務、**稽核原則**、AIMS 監督量測分析評估 | 受稽活動的 **技術層面** |
| 42001 與其他規範文件、AIMS 文件架構、驗證方案 | **附錄 A 所有控制** 及其實施方式 |
| **22989 概念詞彙、5338 生命週期**、AIMS 流程、AI 治理與角色 | **風險管理（23894）**、衝擊評鑑、資料品質、偏差、資安、資料安全；要懂 22989、42005、23894、5259-3、TR 24027、27001、27701 |
| 客戶產業術語與風險、AI 管理工具、政策與業務需求、產業實務 | 產業的 **可信賴 AI** 行為準則（例如 TR 24028）、**軟體開發流程** |
| — | 組織型態與治理對 AIMS 的影響（含委外）、資料科學與 ML 技術 |

團隊要能 **追溯對受影響者造成重大負面影響的事件跡象**，並對應到 AIMS 的管理系統要素。

## 4. 稽核員資格（§7.2.2）— 數字題

**證明方式**：AIMS 專業資格、稽核員登錄、AIMS 訓練與個人資格、**CPD 紀錄**、由授權稽核員見證稽核。

### 一般稽核員

| 條件 | 要求 |
|---|---|
| 學歷 | **大學** 或同等專業教育訓練 |
| 工作經驗 | **至少 4 年全職 IT 或資料保護**，其中 **至少 1 年與 AI 系統相關** |
| 訓練 | 完成 **至少 24 小時** 課程，涵蓋 AIMS 稽核與稽核管理 |
| 稽核經驗 | 擔任 AIMS 稽核員前，有管理系統稽核經驗：**至少 10 個稽核人天，或至少 3 次稽核（含 Stage 1 與 Stage 2）**，**在最近 5 年內**，在資深稽核員監督下取得 |
| 經驗內容 | 至少 **1 次初次或重新驗證** 稽核、至少 **1 次追查** 稽核、文件審查、風險評鑑審查、實施評估、報告撰寫 |
| 維持 | 透過 CPD 與稽核活動維持最新知識 |

這些要求也適用於 **報告審查人員、驗證決定人員、申訴處理團隊**。但如果報告審查與驗證決定由 **不同人** 做，做決定的人可以只有較一般的知識。

### 稽核組長（額外要求）

- 至少參與 **3 次完整管理系統稽核的所有階段**：初始範圍界定、規劃、文件審查、風險評鑑與實施審查、正式報告撰寫。
- 在有經驗、且已做過 **至少 3 次 42001 稽核** 的 AIMS 稽核員監督下取得。
- **過渡期**：標準發布後 **2 年內**，可用 **3 次 27001 稽核** 取代 3 次 42001 稽核。

## 5. 委外（§7.5）

17021-1 允許的委外安排，**不適用於 42001 驗證範圍內的活動**。

## 6. 證書內容（§8.2）

除 17021-1 要求外，還要：
- 由授權人員簽署。
- 標示作為驗證依據的 **SoA 版本**。
- 明確聲明 **AIMS 證書不得作為產品、流程、服務符合性標誌的依據**。

## 7. 機密資訊的存取（§8.4.2）— 情境題

稽核 **前**，驗證機構要請客戶說明哪些 AIMS 資訊因機密或敏感而 **不能給稽核組看**，例如 AIMS 紀錄、控制設計與有效性資訊、**原始碼、原始資料**。

- 驗證機構評估：少了這些資訊還能否充分稽核？
- **不能** → 通知客戶，在取得適當存取安排前 **不進行驗證稽核**。
- 在驗證協議中共同建立保護措施，保護受保護資訊、敏感資訊、智財、商業機密、工具與基礎設施。

智腕科技情境：公司不願讓稽核員看健康模型的訓練資料。驗證機構要評估能否改看 **資料品質報告與抽樣去識別化資料**；若仍不足以判定 A.7，就要先談好存取安排才能稽核。

## 8. 驗證前活動（§9.1）

- **稽核方案** 要涵蓋所有適用要求，並 **識別客戶的 AI 利害關係人角色**；客戶可同時有多重角色，例如 AI 生產者兼 AI 客戶。
- **驗證範圍** 要涵蓋所有與 AI 系統相關的 **重要流程與重要風險**，並反映在 **SoA**。**SoA 是定義驗證範圍的正式文件**。
- **稽核時間**：
  - 總時間包括 **報告撰寫** 與 **稽核組內部討論**。
  - 有不符合時，**評估矯正措施與查證改善的額外時間不計入** 一般稽核時間。
  - 依 42006 附錄 A 計算，附錄 B 有算例。
  - 稽核組內可分配時間，但 **不得減少總稽核時間**。
- **多重管理系統**：可接受與 ISMS、PIMS、風險、QMS 整合的文件，前提是 **AIMS 文件可識別、介面清楚**。合併稽核要能證明所有 AIMS 要求都已滿足、在報告中可明確辨識，且 **整合不得降低稽核品質**。

## 9. 稽核規劃（§9.2）

**稽核目標要包括**：
- 確認 AIMS 的 **有效性**。
- 確認客戶已 **依風險評鑑識別必要控制**。
- 確認 AIMS 目標已達成。

**稽核範圍要確認**：
- 風險評鑑與處理反映實際活動，涵蓋驗證範圍的所有邊界。
- 已反映在 AIMS 範圍與 SoA；**每一驗證範圍至少一份 SoA**。
- 範圍外但有介面的服務已妥善管理並納入風險評鑑，例如 **共用 IT、共用資料庫、共用電信、委外功能**。

**稽核準則**：主要是 42001；可擴充到 **附錄 A 以外的額外控制**。**第一階段** 要審查地區性與法規要求，以便第二階段做風險導向的證據選取。

### 遠距稽核（§9.2.4）

- 要有程序判定遠距稽核的適用程度；**稽核計畫與報告要標示** 是否及在哪些部分用遠距。
- 使用前要做 **風險分析**，至少考慮：雙方基礎設施、產業別、稽核類型（初次、追查、重新驗證）、參與人員能力、客戶過往遠距稽核表現、驗證範圍。
- 風險分析與理由要文件化；風險不可接受就 **不得遠距**；週期中要定期重新檢視。
- 客戶使用 **虛擬據點** 時，遠距技術會是稽核計畫的重要部分。

## 10. 初次驗證（§9.3）

| 階段 | 42006 額外要求 |
|---|---|
| **第一階段** | 取得 AIMS 設計文件；了解 **組織情境、風險評鑑與管理（含控制）、AI 政策、資安政策與目標**、準備度；**結果要形成書面報告**；驗證機構在決定是否進第二階段前要 **審查第一階段報告**，並確認第二階段稽核組能力。獨立審查是一種降低風險的方式，但也可用其他控制。要告知客戶第二階段可能需要的資訊與紀錄 |
| **第二階段** | 依第一階段報告的發現規劃；除了評估有效實施，還要確認客戶 **遵循自己的政策、目標、程序** |

注意差異：17021-1 說第一階段輸出 **不需要** 完整報告；42006 要求第一階段結果 **形成書面報告**。

## 11. 追查稽核（§9.6.2）

- 程序與初次驗證一致。
- 目的：確認持續依 42001 運作、評估組織變動的影響、持續符合驗證要求。
- 依 **AI 系統風險、AI 系統衝擊、組織特性** 調整追查方案，並說明理由。
- 可與其他管理系統合併，但報告要清楚區分。
- 要審查向驗證機構提出的 **申訴與抱怨**。
- 報告要特別包含：**先前不符合的處理結果、SoA 版本、上次稽核後的重大變更**。

## 一張表記住 42006 比 17021-1 多了什麼

| 主題 | 42006 加了什麼 |
|---|---|
| 公正性 | 禁止 AIMS、資安、個資、風險四類顧問；內稽不能改名規避 |
| 責任 | 保險金額與客戶營業額相當 |
| 能力 | AI 專業知識；每位成員 vs 團隊整體 |
| 資格 | 大學、4 年 IT 或資料保護（1 年 AI）、24 小時訓練、10 人天或 3 次稽核（5 年內） |
| 組長 | 3 次完整稽核；過渡期 27001 可替代 |
| 委外 | 42001 範圍內活動不得委外 |
| 證書 | SoA 版本、非產品證書聲明 |
| 機密 | 稽核前確認原始碼與資料等存取 |
| 範圍 | AI 角色、重要流程與風險、SoA 是範圍正式文件 |
| 時間 | 含報告與內部討論；矯正查證時間另計 |
| 遠距 | 先做風險分析並文件化 |
| 第一階段 | 要書面報告並經審查 |
| 追查 | 依 AI 風險與衝擊調整；報告列 SoA 版本 |

## 考試陷阱

- 「驗證機構可為客戶提供個資保護顧問，只要不是 AIMS 顧問」→ 錯，四類都禁止。
- 「把內部稽核改稱為差距評估就不違反公正性」→ 錯。
- 「AIMS 證書可證明 AI 產品符合標準」→ 錯。
- 「每位稽核員都要懂附錄 A 所有控制的實施」→ 錯，團隊整體具備即可；但每位要懂 42001 本身。
- 「矯正措施查證的時間可算入一般稽核時間」→ 錯。
- 「客戶不給看原始碼，稽核員就直接開不符合」→ 錯，應在稽核前評估存取，必要時不進行稽核。
