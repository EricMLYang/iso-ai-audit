# ISO/IEC 22989 — AI 概觀：概念、角色、生命週期（讀書筆記）

> 對應課程資源：課程參引〈AI 概觀〉（單元 2、單元 4 必看）。
> 自己的話整理；詞彙辨析另見 [ISO22989_AI詞彙_易混辨析.md](ISO22989_AI詞彙_易混辨析.md)。生命週期流程細節見 [AI系統生命週期_ISO5338.md](../AI系統生命週期_ISO5338.md)。

## 1. AI 系統跟傳統系統不同的四個特性（§5.1）

| 特性 | 白話 | 智腕科技例子 |
|---|---|---|
| 互動 | 輸入來自感測器或人，輸出可觸發其他裝置或回應人 | 手錶心率感測 → App 推播 |
| 情境感知 | 可整合結構化、非結構化與感官輸入 | 生理資料＋行事曆＋位置 |
| 監督程度不一 | 依應用在不同程度的人為監督下運作 | 異常心律只「建議就醫」，不自動通報 |
| 自適應 | 可用動態資料再訓練、更新運作 | 個人化運動建議隨使用者資料調整 |

## 2. 強／弱 AI vs 通用／狹隘 AI（§5.2）

- **強 vs 弱** 是哲學分類：系統是否「真正理解」自己在做什麼。
- **通用（AGI）vs 狹隘（ANI）** 是技術分類：能處理的任務範圍。
- 現有 AI 都屬於 **狹隘 AI**。AGI 是否可行仍未知。

## 3. AI 代理的四種架構（§5.3）

代理透過 **感測器** 感知環境、透過 **致動器** 採取行動。

| 類型 | 依據 |
|---|---|
| 反射型 | 只看當前狀況 |
| 基於模型 | 有環境模型，可推想行動後果 |
| 基於目標／效用 | 有效用函數，選最能達成目標的行動 |
| 學習型 | 收集環境資訊、提升自身績效 |

## 4. 資料 → 資訊 → 知識（§5.4、§7.3）

- AI 語境中的「知識」是 **純技術名詞**，指內容，不是理解能力。
- 資訊是系統「觀察到的」；知識是系統從觀察中「保留並組織起來的」。
- **宣告性知識** 說「是什麼」，例如某種蘑菇有毒。**程序性知識** 說「怎麼做」，例如查圖鑑或問藥師。
- **啟發式系統** 不學習，用固定知識庫，例如傳統專家系統。**機器學習系統** 從資料學出模型。

## 5. 符號、次符號、混合 AI（§5.9）

- 符號 AI：顯式編碼、邏輯推理，**可解釋性高**。
- 次符號 AI：隱式編碼、統計方法，例如類神經網路。
- 現代系統多為兩者混合，稱 **混合 AI（hybrid AI）**。

## 6. 資料處理流程（§5.10）

採集 → 探索性分析 → 標註 → 準備 → 過濾 → 正規化 → **去識別化** → 品質檢查（含 **資料投毒** 檢查）→ 抽樣 → 增強 → 標籤。

稽核用：過濾可能 **引入偏差**，要檢查過濾的效果。含個資時要先去識別化，可參考 ISO/IEC 20889。

**AI 語境下「確證（validation）」的特殊意義**：一般軟體工程中 validation 是確認需求是否滿足；在 AI 中，「驗核資料」是用來 **設定設計參數**，例如調超參數，發生在評估之前。考題若問「AI 語境下的 validation data 用途」，答案是調整與選模型，不是最終評估。

## 7. ML、NN、DL 的俄羅斯娃娃關係（§5.11）

機器學習 ⊃ 類神經網路 ⊃ 深度學習。

- 決策樹、SVM、貝氏網路屬於 ML，但不是 NN。
- 單一隱藏層的淺層網路是 NN，但不是 DL。
- AI 也可以不靠 ML 提升績效，例如加規則、改搜尋演算法、升級硬體。

| 學習方式 | 典型任務 |
|---|---|
| 監督式 | 分類、迴歸 |
| 非監督式 | 分群、關聯、降維 |
| 半監督式 | 標註成本太高時 |
| 強化學習 | 試錯、最大化回報 |
| 遷移學習 | 把一個問題學到的知識用到另一個問題 |

## 8. 漂移與再訓練（§5.11.9）— 高頻考點

| 現象 | 什麼變了 | 處理 |
|---|---|---|
| **資料漂移（data drift）** | 生產資料的 **統計特徵** 變了，例如感測器解析度改變 | 用更能代表現況的新資料再訓練 |
| **概念漂移（concept drift）** | **決策邊界** 變了，資料本身可能沒變，例如新法規改變合法定義 | 重新標註目標變數再訓練 |
| **災難性遺忘** | 再訓練時新資料覆蓋舊知識 | 持續學習要設法保留先前知識 |

持續學習是再訓練的特例：高頻率、不中斷營運。挑戰是學習中仍要確保正確運作，所以要 **在生產中確證**，並保存生產資料以備日後訓練。

智腕科技例子：新款手錶感測器換供應商 → 資料漂移。衛福部更新心律不整判定指引 → 概念漂移。

## 9. 自動化等級表（§5.13）— 必背

| 等級 | 名稱 | 誰控制 |
|---|---|---|
| 6 | 自主（autonomy） | 系統可自行修改使用領域或目標 |
| 5 | 完全自動化 | 無外部干預完成 **整個任務** |
| 4 | 高度自動化 | 無外部干預完成 **部分任務** |
| 3 | 有條件自動化 | 外部代理 **隨時準備接管** |
| 2 | 部分自動化 | 部分子功能自動，仍在外部控制下 |
| 1 | 協助 | 系統協助操作人員 |
| 0 | 無自動化 | 人完全控制 |

- 等級 1～5 屬於 **他治性（heteronomous）**，等級 6 才是自主。
- 22989 刻意不用「自主」描述自動化，因為即使最先進的 AI 也不是自我管理的。
- **人機協作（human-machine teaming）**：機器補充而非取代人；以補強人類認知為目的時稱 **智能增強（intelligence augmentation）**。

## 10. 可信賴性的子特性（§5.15）

| 特性 | 重點 |
|---|---|
| 強健性 | 面對非典型輸入仍維持在可接受範圍；輸出不理想但仍在範圍內也算強健 |
| 可靠性 | 在規定條件與期間內執行所需功能；受強健性、可推廣性、一致性、強韌性影響；**備援系統** 可提升可靠性 |
| 強韌性 | 事故後快速恢復；可接受 **降級運作** |
| 可控性 | 外部代理能接管；關鍵是界定 **誰能控制哪些元件** |
| 可解釋性 | 決策影響個人時尤其重要；規則型與決策樹較易解釋，深度學習較難 |
| 可預測性 | 不應只靠人的主觀感覺，宜用 **統計保證** 等客觀準則 |
| 透明性 | 揭露目標、限制、設計選擇、資料來源；可能與資安、隱私、保密衝突 |
| 偏差與公平 | 偏差本身是 ML 區分案例的基礎；**不公平** 才是不合理的差別待遇。訓練資料偏差是主要來源，參考 TR 24027 |

## 11. 查證 vs 確證的五種組合（§5.16）

系統可能是：完全可查證；部分可查證、部分可確證；不可查證但可確證；不可查證但部分可確證；既不可查證也不可確證。ISO 9000 把查證也稱為 **符合性測試（compliance testing）**。

## 12. 管轄權與社會影響（§5.17、§5.18）

- 跨境部署時法律要求可能不同，包括資料蒐集、使用、**處置**。緩解：準備階段就盤點、各管轄區的遵法計畫、全生命週期監控遵法、監控法規變化、彈性設計。
- **評估風險等級的面向**：活動類型（建議 vs 直接行動）、有無外部監督、監督形式（自動或人工）、任務的倫理相關性、決策透明度、自動化程度。
- 低風險例：只給建議、無倫理相關性。高風險例：直接影響人命、無外部監督、決策不透明。

智腕科技外銷歐盟要多考慮 GDPR，見 [法規與標準總覽.md](../法規與標準總覽.md)。

## 13. AI 利害關係人角色（§5.19）— 必考

| 角色 | 子角色 | 智腕科技 |
|---|---|---|
| AI 提供者（provider） | 平台提供者；產品或服務提供者 | ✅ 提供 WristAI 與雲端服務 |
| AI 生產者（producer） | **AI 開發者**：模型設計者、模型實作者、計算查證者、模型查證者 | ✅ 自行開發健康模型 |
| AI 客戶（customer） | AI 使用者 | 購買手錶的消費者、企業健康方案客戶 |
| AI 夥伴（partner） | 系統整合商、資料提供者、**AI 稽核員**、AI 評估者（可為第三方測試實驗室） | 雲端供應商、標註外包商 |
| AI 主體（subject） | 資料主體（含訓練資料主體）、其他主體 | 手錶配戴者、被同步聯絡人資料的第三人 |
| 相關主管機關 | 政策制定者、監管機關 | 數位發展部、衛福部、個資主管機關 |

- 一個組織可同時承擔多個角色。
- 注意 **稽核員屬於「AI 夥伴」**，考題常用這點出陷阱。
- 42001 §4.1 要求組織判定自己的角色；角色決定附錄 A 哪些控制適用，見 [條款4_組織情境_重點解說.md](../條款4_組織情境_重點解說.md)。

## 14. 生命週期階段（§6）

**初始 → 設計與開發 → 查證與確證 → 部署 → 運作與監視 → 持續確證 → 重新評估 → 汰除**。

| 階段 | 重點產出 |
|---|---|
| 初始 | 目標、需求（含部署、營運、汰除的需求）、**風險處理計畫**、透明與問責紀錄、成本、資源、可行性 |
| 設計與開發 | 方法、架構、程式、訓練資料、實施風險處理 |
| 查證與確證 | 功能與效能測試、測試資料與開發資料分離、驗收、風險審查 |
| 部署 | 軟體與模型可 **分開部署**；審查並更新風險處理計畫 |
| 運作與監視 | 監視事故並回報給 AI 提供者、修復、更新、使用者支援 |
| 持續確證 | 持續學習時才有；測試資料也要更新以代表現況 |
| 重新評估 | 評估運作結果、修正目標與需求 |
| 汰除 | 退役與丟棄（含資料）或替換 |

AI 發布管理和傳統軟體不同：除了程式差異，還要管 **模型差異** 與 **訓練資料差異**。

## 15. 預測 → 決策 → 行動（§7.4）

- **預測**：第一個輸出，例如還款可能性。
- **決策**：選定行動方案，可由系統或人做出；全自動時靠人設定的 **決策門檻值**。
- **行動**：開始影響真實世界的那一步。
- 分類錯誤分兩種：**偽陽性**（實際陰性卻判陽性）與 **偽陰性**（實際陽性卻判陰性）。智腕科技的心律警示中，偽陰性的後果比偽陽性嚴重，這應反映在風險準則與門檻設定上。

## 16. 生態系統、雲與邊緣（§8）

- 生態系統由上而下：AI 系統 → AI 功能 → 機器學習／工程 → 大數據與資料來源、雲與邊緣 → 資源池（GPU、NPU、ASIC 等）。
- 專家系統的組成：**知識庫**（宣告性知識）＋ **推論引擎**（程序性知識）＋ 使用者介面。
- 三種雲邊訓練設計：**雲端訓練、邊緣部署**；**邊緣訓練**（個人化）；**雲邊混合**（雲當參數伺服器，或邊緣模型上傳後分發）。
- 邊緣運算的理由：低延遲、斷線時仍可運作、在裝置端保護個資。智腕科技的手錶端推論正屬此類。

## 考試陷阱

- 「AI 稽核員屬於 AI 提供者角色」→ 錯，屬於 AI 夥伴。
- 「等級 5 完全自動化屬於自主」→ 錯，仍是他治性。
- 「概念漂移一定伴隨資料分布改變」→ 錯，資料可能沒變。
- 「偏差一律有害」→ 錯，不公平才是問題。
- 「可預測性應以使用者的主觀感受衡量」→ 22989 建議用客觀、可量化準則。
- 「軟體和模型必須一起部署」→ 錯，可分開部署。
