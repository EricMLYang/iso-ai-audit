# 過程導向與風險思維 — 實作步驟（讀書筆記）

> 對應課程資源：單元 2〈管理系統如何實踐過程導向方法〉、〈ISO 9001:2015 基於風險的思維〉。原文以 ISO 9001 為例；本檔改用智腕科技的 AIMS 說明。
> 自己的話整理。觀念總覽見 [管理系統基礎_HLS_PDCA_風險思維.md](../管理系統基礎_HLS_PDCA_風險思維.md) §3～§5；本檔補 **步驟** 與 **稽核時怎麼看**。

## 1. 三個概念的關係

| 概念 | 角色 |
|---|---|
| **過程導向** | 把組織的流程當作 **整合的系統** 來管理 |
| **PDCA** | 管理流程與系統的 **工具**，同時適用於整個系統、單一流程、日常營運活動 |
| **風險思維** | **貫穿** 過程導向與 PDCA 的每個階段 |

過程（process）的定義：使用輸入產出 **預期結果** 的一組相互關聯或互動的活動。輸入輸出可以有形（材料、裝置），也可以無形（資料、資訊、知識）。

## 2. 用 PDCA 建立過程導向的十二個步驟

| PDCA | 步驟 | 智腕科技 AIMS 範例 |
|---|---|---|
| P | 1. 定義組織全景：職責、關注方與其需求 | 對應作業 4 的 AIMS-FRM-001-01、001-02 |
| P | 2. 定義範圍、目標、政策 | AIMS-FRM-001-05 範圍界定；AI 政策 |
| P | 3. 確定組織中的流程：管理、資源、營運、監督、量測、分析、評估、改進 | AI 開發流程、資料管理流程、事件處理流程 |
| P | 4. 確定流程的 **順序與互動**：輸入輸出、介面、依賴關係、**互動中的有效性風險** | 資料標註 → 模型訓練 → 驗證 → 部署 |
| P | 5. 指定 **流程負責人（process owner）** 與問責；可設跨職能的管理系統團隊 | 資料科學部長負責模型訓練流程 |
| P | 6. 定義 **文件化資訊需求**：依 **風險思維** 決定哪些流程要正式記錄 | 高風險的健康預警模型流程要寫 SOP；低風險的內部排班工具不必 |
| P | 7. 定義流程中的介面、風險、活動：輸入輸出、非預期結果的風險、內建控制 | 標註品質不佳 → 模型偏差 |
| P | 8. 定義監督量測要求：在哪裡量、怎麼量、要不要留紀錄 | 偽陰性率、漂移指標、事件頻率 |
| D | 9. 實施：執行流程、監督、控制（含外包） | — |
| D | 10. 定義所需資源：人力、基礎設施、環境、資訊、知識、材料、財務 | GPU 預算、標註人力 |
| C | 11. 對照目標查證流程：監督、量測、分析、評估、審查、**稽核** | 內部稽核、模型績效報告 |
| A | 12. 改善：審查與變更流程；矯正措施要找 **根本原因** | 修改標註規範 |

### 重點觀念

- **沒有「必須正式定義的流程清單」**。要記錄哪些流程，依組織規模、活動型別、流程複雜度、**關鍵性**、問責需要來決定。
- 文件化的方法（流程圖、使用者故事、清單、影片）**本身不是目標**，只是手段。
- **系統思維**：一個流程的事件可能在另一個依賴流程中產生因果，**原因和影響可能不在同一個流程裡**。
- 問題解決的基本步驟：定義問題 → 蒐集分析資料 → 選擇並實施解法 → 評估有效性 → **納入例行作業**。
- 即使已達成目標，仍應透過小步改善、突破性改進或創新持續提升。

## 3. 風險思維

### 為什麼取代「預防措施」條款

- 舊版 ISO 9001 把預防措施當成獨立條款；2015 年起改成 **整個系統都考慮風險**，所以 **預防內建在規劃、營運、分析、評估之中**。
- 風險思維 **已經是過程導向的一部分**，不是取代它。
- 不是所有流程風險一樣：有些需要更仔細、更正式的規劃與控制。

### 風險 vs 機會

- 風險的影響可以是負面，也可以是正面。
- **機會不是風險的正面**。機會是「使做某事成為可能的一組情況」；**抓或不抓機會都帶來不同程度的風險**。
- 這跟 31073 的說法一致，見 [ISO31073 筆記](ISO31073_風險管理詞彙_易混辨析.md)。

### 風險思維在 HLS 各條款的位置

| 條款 | 怎麼體現 |
|---|---|
| 4 | 確定管理系統流程，並處理其風險與機會 |
| 5 | 最高管理階層推動風險思維的認知 |
| 6 | 識別並處理風險與機會 |
| 7 | 提供 **「適當」** 的資源。只要看到「適當」「合適」，就隱含風險判斷 |
| 8 | 管理營運流程，同樣隱含風險判斷 |
| 9 | 監督、量測、評估 **處理風險措施的有效性** |
| 10 | 矯正、預防、減少不良影響，並 **更新風險與機會** |

### 風險思維的五步驟（過馬路比喻）

1. **識別風險**：依情境而定，例如車流、天氣、能見度。
2. **了解風險**：什麼可接受、什麼不可接受；目標之間如何權衡，例如安全比準時重要。
3. **規劃行動**：避免、消除或降低，例如選擇沒車時過馬路。
4. **實施並檢查有效性**：安全準時抵達了嗎？
5. **從經驗學習並改進**：依時段改用天橋；再想創新，例如改成線上會議。

### 套到智腕科技

| 步驟 | 範例 |
|---|---|
| 識別 | 新版睡眠模型在高齡使用者的誤判率可能升高 |
| 了解 | 不可接受：漏報睡眠呼吸中止；可接受：睡眠分期略有誤差 |
| 規劃 | 先對 65 歲以上族群灰度發布，設定漏報率門檻 |
| 實施與檢查 | 監控兩週，漏報率未超標 |
| 學習改進 | 把「依年齡分層驗證」寫入模型驗證程序；考慮蒐集更多高齡資料 |

## 4. 稽核員怎麼用

- 問流程負責人：「這個流程的 **輸入、輸出、上下游介面** 是什麼？哪個環節出錯最傷？」能回答得出來，代表過程導向有落實。
- 看到程序裡寫「適當的資源」「適當的頻率」，就追問 **依據什麼風險判斷這是適當的**。
- 看文件化程度是否與 **流程關鍵性** 相稱：高風險 AI 流程沒有程序、低風險流程反而文件一大堆，都值得追問。
- 矯正措施有沒有找 **根本原因**，還是只做了修正？

## 考試陷阱

- 「ISO 管理系統標準要求每個流程都必須文件化」→ 錯，依風險與關鍵性決定。
- 「風險思維取代了過程導向」→ 錯，風險思維是過程導向的一部分。
- 「HLS 標準已刪除預防，所以不需要預防」→ 錯，預防已內建於整個系統。
- 「機會就是正面的風險」→ 錯。
- 「PDCA 只適用於整個管理系統」→ 錯，也適用於單一流程與營運活動。
