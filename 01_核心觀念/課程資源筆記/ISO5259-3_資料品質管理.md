## 關鍵定義

- **資料品質**：說明資料 **滿足資料品質要求程度** 的主張陳述（claim）。
- **資料品質計畫**：為達成資料品質目標而定的實務、流程與資源。
- **開發介面協議（DIA）**：客戶與供應商之間，規定開發期間各自負責的活動、證據與工作產出。DIA 用在 **開發階段**，供應協議用在 **生產階段**。

資料品質有 **內在** 與 **系統相依** 兩個成分，同一份資料可能適合 A 用途而不適合 B 用途。

## 整體資料品質管理（第 6 章）

| 主題 | 組織要做的事 |
|---|---|
| 資料品質文化 | 訂規則與流程、執行、**整合到品質與風險管理**、文件化、給資源、監控改善、授權、傳達政策 |
| 資料品質議題 | 溝通、分析、評估、解決、結案；無法結案就 **上報或委派**；縮小 ML 專案範圍也是一種解法 |
| 能力 | 記錄所需技能與工具、確保人員勝任、保存訓練與經驗紀錄 |
| 資源 | 軟體、IT 基礎設施、人員 |
| 管理系統整合 | 整合到 42001、9001 等；管理 **雙重角色的利益衝突**，例如使用者同時是資料貢獻者 |
| 文件化 | 依角色可理解；語言不通要提供摘要；要讓 **未來接手的人** 判斷能否再利用 |
| 稽核與評估 | 稽核流程符合度；在 **資料提供之前** 評估資料品質；持續學習或串流資料要定期評估；可用代表性子集評估 |
| 確認審查 | 依 5259-2 的量測指標確認；關鍵工作產出在資料提供前要做確認審查；可委派執行，但 **責任不移轉** |

## 資料品質管理生命週期（DQMLC）— 排序題素材

**動機與概念化 → 規格 → 規劃 → 取得 → 前處理 → 增強 → 提供 → 退役**

貫穿所有階段的 **四個水平流程**：**查證與確證、變更管理、組態管理、風險管理**。即使裁剪生命週期，這四項仍要做。

DQMLC 不規定時間順序，可合併、拆分、迭代、平行，或有理由時省略。但 **事後修正比源頭預防難**，所以品質管理從生命週期一開始就要建立。

| 階段 | 重點要求 | 智腕科技例子 |
|---|---|---|
| 動機與概念化 | 記錄需求動機、範圍、目的、預期用途、品質要求；**關注方分析**、找出衝突的品質要求；可行性分析 | 為何需要夜間血氧資料？ |
| 規格 | 性質、目標、法律、安全與資安、**非預期偏差**、隱私（**資料最小化**）、品質模型；格式（編碼、頻率、解析度、語意、值域）；**訓練、確證、測試子集不重疊**（除非用 K-fold、bootstrap 等方法）；代表性與規模 | 取樣頻率、各年齡層比例 |
| 規劃 | 資料品質計畫：目標、資源、法律、更新流程、**可追溯與可重現**；各階段子計畫 | DQ 計畫文件 |
| 取得 | 優先考慮再利用、轉換、購買授權、新蒐集、產生；**委外取得仍由組織負責**；新蒐集要說明理由、方法、感測器規格與位置、**匿名化或假名化**、量測尺度；資料處理要有品質審查、存取控制、溯源、版本、備份、**資料負責人** | 臨床合作醫院資料、政府開放資料 |
| 前處理 | 至少說明如何處理缺漏、重複、離群、**偏差與漂移**、非標準值、不必要資料、轉換與正規化、去識別化；注意部分轉換 **不可逆** | 去除脫錶期間的雜訊 |
| 增強 | 標註規格、技能、選樣、品管；**標註人員的身心影響與緩解**；計算式增強要記錄工具、特徵、日誌 | 心律標註外包 |
| 提供 | 可稽核的符合證據；**提供過程不改變資料**；身分驗證與存取；版本控制；附文件：使用範圍、使用說明、統計特性、關注方、接收者責任、使用環境、驗收測試、溝通與更新方式；決定是否追蹤使用情形並建立回饋管道 | 交給模型團隊的資料包 |
| 退役 | **刪除或移轉** 二擇一 | 使用者刪帳 |

### 退役的細節（容易出題）

- **移轉**：確認接收者有資格、證明不違反義務、保留接收者同意證據、移轉報告 **獨立驗證**。
- **刪除**：證明不違反保存義務；確認沒有使用者還需要它，包括要再訓練的系統；**所有位置都要刪，含自動備份**；記錄刪除方法；評估 **能否從已訓練模型還原資料**；刪除報告獨立驗證；可考慮捐贈到公共領域。
- **應要求的部分刪除**（例如個資當事人要求）：刪除後評估剩餘資料是否仍符合規格；不符合就通知關注方並提供緩解；無法緩解就整批退役。

智腕科技：使用者行使個資法刪除權時，要評估健康模型是否記住了該使用者，以及剩餘資料是否仍有代表性。

## 水平流程

| 流程 | 要點 |
|---|---|
| 查證與確證 | 每階段要有可客觀評估的品質目標，也就是 **品質關卡**；輸入資料通過查證確證後才能進入下一階段；記錄限制 |
| 組態管理 | 可唯一識別、可重現；每個有效組態都要符合其品質要求 |
| 變更管理 | 變更 **前** 先規劃；變更申請要有唯一編號、日期、原因、組態、決策理由；分析影響範圍、關注方、品質、時程；授權人員決定；資料或用途變更要觸發重新評估 |
| 風險管理 | 考慮超出預期用途但 **可合理預見** 的資料使用；量測指標依風險程度選擇；向關注方溝通資料風險；可參考 23894 |

## 供應鏈、工具、相依性

- **供應鏈**：選供應商要看能否符合本標準；詢價文件寫明要求；與供應商簽 **DIA**，包含角色、活動、責任、基準、品質評估、**允許使用者指定的稽核員存取資源**、運作與退役期間的責任。
- **資料處理工具**：至少評估取得（爬蟲、問卷、感測器）、前處理、品質評估、標註、儲存、傳輸、保護（防火牆、加密）七類工具對品質的影響。
- **相依性**：內部（組織可控的處理活動）與外部（雲端、委外標註），都要識別並緩解。

## 專案層級要求（第 12 章）

- 界定範圍、動機、使用條件、預期用途；記錄 **已知限制**，例如維護期間、技術限制、應用領域限制、**失敗的使用案例**，並持續更新。
- 資料品質要求要 **明確無歧義**、可識別、連結到資料、納入組態管理、經過驗證；最好有唯一編號與狀態。
- 指派 **專案經理** 與 **品質經理**。
- 裁剪要寫進計畫並說明理由。
- 前一階段資訊不足的風險沒處理好，就 **不宜進入下一階段**。

## 稽核員可以問的問題

1. 這個模型的訓練、確證、測試資料，從哪裡證明 **不重疊**？
2. 委外標註的 **DIA** 或合約裡，有沒有允許稽核的條款？
3. 最近一次資料規格變更的 **變更申請單** 在哪裡？有沒有觸發重新評估？
4. 使用者要求刪除資料時，**備份** 怎麼處理？有沒有評估模型記憶？
5. 資料提供前的 **確認審查紀錄**？

## 考試陷阱

- 「委外取得資料，品質責任就移轉給供應商」→ 錯。
- 「確認審查委派他人執行後，責任也一併移轉」→ 錯。
- 「刪除資料只需刪除主要資料庫」→ 錯，含備份等所有位置。
- 「DIA 適用於生產階段」→ 錯，DIA 用於開發階段。
- 「裁剪生命週期時可省略變更管理」→ 錯，四個水平流程一定要做。
