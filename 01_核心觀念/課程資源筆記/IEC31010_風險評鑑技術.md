# IEC 31010 — 風險評鑑技術（讀書筆記）

> 對應課程資源：課程參引〈IEC 31010 風險評鑑技術〉（單元 2、單元 6）。課程頁依 2009 版編排，2019 版已更新，但核心觀念相同。
> 自己的話整理。31010 是 **31000 的支援標準**，談「怎麼選、怎麼用」評鑑技術；**不用於驗證、法規或合約目的**。

## 風險評鑑要回答的五個問題

1. 可能發生什麼？為什麼？（鑑別）
2. 後果是什麼？
3. 發生的可能性多高？
4. 有沒有因素能降低後果或可能性？（現有控制）
5. 風險等級可否容忍或接受？需要進一步處理嗎？（評估）

## 鑑別方法三大類

| 類別 | 例子 |
|---|---|
| 以證據為基礎 | 查檢表、歷史資料審查 |
| 系統化小組 | 專家以結構化提示逐步鑑別 |
| 歸納推理 | HAZOP |

輔助技術：**腦力激盪、德爾菲法（Delphi）**。

提醒：人為與組織因素的偏差要跟硬體、軟體事件 **一樣納入** 鑑別。

## 分析的三種精度

| 方法 | 做法 | 注意 |
|---|---|---|
| 定性 | 高、中、低等級 | 用語要明確定義，準則依據要記錄 |
| 半定量 | 數值量尺，用公式結合後果與可能性 | 量尺可線性或對數 |
| 定量 | 估算實際數值 | 資料不足時不一定可行；計算結果仍是 **估計值**，不要表現得比資料更精確 |

### 控制評鑑的三個問題

- 這個風險有哪些既有控制？
- 足以把風險控制到可容忍嗎？
- 實務上真的照預期運作嗎？需要時能證明有效嗎？

只有在有 **適當文件化與保證過程** 時，才能有信心回答。這正是稽核員要找的證據。

### 後果分析要點

- 同時看 **高後果低機率** 與 **低後果高機率**；經常發生的小問題可能有很大的 **累積影響**。
- 考慮立即後果、一段時間後的後果，以及 **二次後果**（對相關系統或組織的衝擊）。

### 估算可能性的三種方式

1. **歷史資料外插**：資料發生率極低時非常不確定；「過去沒發生」不代表未來不會發生。
2. **預測技術**：故障樹、事件樹；要考慮 **共同原因失效**。
3. **專家意見**：德爾菲法、成對比較、類別分等、絕對機率判斷。

### 初步分析（篩選）

把資源放在最重要的風險上，但 **不要篩掉經常發生、有累積影響的低風險**。初步假設與結果要文件化。

### 不確定性與敏感度

- **不確定性分析**：結果的變異來自參數與假設。
- **敏感度分析**：個別輸入參數改變時，風險變化多大；用來決定哪些資料需要更精確。

## 風險評估的三區帶（ALARP）— 必考

| 區帶 | 意義 | 做法 |
|---|---|---|
| 上層 | **不可容忍** | 不論成本，一定要處理 |
| 中間（灰色區） | 權衡成本與效益 | 降到 **合理可行的最低（ALARP）** |
| 下層 | 可忽略 | 不需處理 |

ALARP：高風險要持續降低，直到再降低的成本與效益 **完全不成比例** 為止。

## 選擇技術的原則

**好技術的三個特性**：理由充分且適合情況；結果能增進對風險本質與處理方式的理解；**可追溯、可重複、可查證**。

**選擇時考慮的因素**：研究目標、決策者需求、風險類型與範圍、後果的潛在幅度、專家與資源、資料可得性、未來修改需求、法規與合約要求。另外看三大影響：**資源**、**不確定性的本質與程度**、**複雜性**。

「做得好的簡單方法」常比「粗略做完的複雜方法」更好。投入的努力要與風險等級相稱。

## 生命週期應用

- 概念階段：決定要不要做，比較替代方案。
- 設計開發：確保系統風險可容忍、改善設計、成本效益研究、找出對後續階段的衝擊。
- 運作階段：協助制定正常與緊急程序。

跟 AI 生命週期對照，見 [AI系統生命週期_ISO5338.md](../AI系統生命週期_ISO5338.md)。

## 評鑑文件建議內容

目標與範圍、系統描述、內外部全景、**風險準則及其正當性**、限制與假設、方法論、鑑別結果、資料與來源、分析與評估結果、**敏感度與不確定性分析**、需監測的關鍵假設、結論與建議、參考資料。

## 常見技術速覽（附錄 B 名稱，供配對題）

| 技術 | 適用 |
|---|---|
| 腦力激盪、結構化訪談、德爾菲 | 鑑別 |
| 查檢表、初步危害分析（PHA） | 鑑別 |
| HAZOP（危害與可操作性分析） | 流程偏差鑑別 |
| SWIFT（結構化假設分析） | 小組快速鑑別 |
| 情境分析 | 未來不確定性 |
| BIA（業務衝擊分析） | 中斷對營運的影響 |
| 根本原因分析（RCA） | 事後找原因 |
| FMEA／FMECA（失效模式與效應分析） | 元件失效 |
| 故障樹（FTA） | 從頂端事件往下找原因 |
| 事件樹（ETA） | 從起始事件往後推結果 |
| 因果分析、因果圖（魚骨圖） | 原因結構 |
| 蝴蝶結分析（Bow-tie） | 原因與後果兩側的控制 |
| 保護層分析（LOPA） | 安全防護層 |
| 人因可靠度分析（HRA） | 人為錯誤 |
| 馬可夫分析、蒙地卡羅模擬、貝氏網路 | 定量 |
| 後果與可能性矩陣 | 評估、排序 |
| 成本效益分析 | 處理選擇 |

智腕科技可用的組合：用 **FMEA** 分析手錶感測器與模型的失效模式，用 **蝴蝶結** 呈現「健康資料外洩」前後兩側的控制，用 **後果與可能性矩陣** 對齊 RC-xxx 風險清冊。

## 考試陷阱

- 「31010 可用於驗證」→ 錯。
- 「定量分析一定比定性準確，應優先採用」→ 錯，取決於資料與需求。
- 「篩選時應排除所有低風險」→ 錯，要保留有累積影響的低風險。
- 「歷史上沒發生過的事件機率為零」→ 錯。
- 「ALARP 中間區帶的風險一律要降到零」→ 錯，降到合理可行即可。
