## 0. 一張圖看懂關係

```
                          ┌──────────── 法律（WHAT：必須做到什麼）────────────┐
                          │ 台灣：人工智慧基本法、個資法、資安法、醫材法、消保法 │
                          │ 國際：EU AI Act、GDPR                              │
                          └───────────────┬───────────────────────────────────┘
                                          │ 透過 §4.1 外部議題、§4.2 關注方要求 進入 AIMS
                                          ▼
 治理層      ISO/IEC 38507（董事會如何治理 AI）
               │ 指揮
 管理系統層  ISO/IEC 42001（AIMS 要求，可驗證）◄── 詞彙與概念 ISO/IEC 22989
               │  ├─ 風險：ISO/IEC 23894 ◄── ISO 31000（原則/架構/流程）、ISO 31073（詞彙）、IEC 31010（技術）
               │  ├─ 衝擊：ISO/IEC 42005（AI 系統衝擊評鑑）
               │  ├─ 生命週期：ISO/IEC 5338 ◄── ISO/IEC/IEEE 15288（系統生命週期）
               │  ├─ 資料：ISO/IEC 5259 系列（5259-3 資料品質管理）
               │  └─ 整合：ISO/IEC 27001（資安）、ISO/IEC 27701（隱私）
               ▼
 稽核層      ISO 19011（怎麼稽核，指引）
               ▼
 驗證層      ISO/IEC 17021-1（驗證機構通用要求）◄── ISO/IEC 42006（AIMS 驗證機構特定要求）
               ▲
 認證層      ISO/IEC 17011（認證機構要求；台灣為 TAF）
```

**三句話記住：**
1. **法律** 說「要做到什麼」，違反有罰則；**標準** 說「怎麼有系統地做到」，自願採用。
2. 42001 驗證 **不等於** 合法；但 42001 要求組織 **識別並處理適用法規**，稽核員會查這件事。
3. 要求標準（42001、27001、17021-1、42006）用「應」，可被稽核；指引標準（19011、23894、42005、38507、22989）用「宜」，不能拿來發證。

## 2. 台灣法律

### 2.1 人工智慧基本法

| 項目 | 內容 |
|---|---|
| 狀態 | 2025-12-23 立法院三讀，**2026-01-14 公布施行** |
| 主管機關 | 中央：**國家科學及技術委員會**；地方：直轄市、縣市政府；涉及各目的事業者由各該機關辦理。行政院設「國家人工智慧戰略特別委員會」協調跨部會 |
| 性質 | **綱領性（基本法）**：定原則與政府義務，本身原則上 **不直接設罰則**，具體規範由各部會後續子法與現行法規調適 |
| 七大原則 | ① 永續發展與福祉 ② 人類自主 ③ 隱私保護與資料治理 ④ 資安與安全 ⑤ 透明與可解釋 ⑥ 公平與不歧視 ⑦ 問責 |
| 其他重點（依各方整理） | 風險導向治理（推動與國際接軌的 AI 風險分級框架）、資料開放與個資保護兼顧、勞動權益保障、政府各機關檢討調適相關法規 |
| 對 AIMS 的意義 | 七大原則幾乎一一對應 42001 附錄 C 的 AI 目標與附錄 A 控制（見 §4 對照表）；屬 §4.1 外部議題、§4.2 主管機關要求 |

### 2.2 個人資料保護法（個資法）

| 項目 | 內容 |
|---|---|
| 主管機關 | 個人資料保護委員會（個資會）籌設中，逐步承接監理；非公務機關監理移轉有過渡期 |
| 修法 | 2023 修正：設個資會、提高罰鍰；**2025-11-11 修正公布**（施行日期由行政院定）：強化個資會監理、**事故向個資會通報義務**、公務機關設個資保護長 |

**重要條文（AI 系統常碰到）**

| 條 | 白話 | AI／穿戴情境 |
|---|---|---|
| §2 | 定義：個資、蒐集、處理、利用 | 生理數據、位置、裝置 ID 都可能是個資 |
| §3 | 當事人權利：查詢閱覽、製給複本、補充更正、停止蒐集處理利用、刪除（不得預先拋棄） | App 要提供行使管道 |
| §5 | 誠信、不逾越特定目的必要範圍、正當合理關聯 | 健康資料不得挪作廣告 |
| §6 | **特種個資**：病歷、醫療、基因、性生活、健康檢查、犯罪前科，原則禁止蒐集處理利用，例外情形才可 | 心率、血氧、睡眠是否屬「醫療／健康檢查」需判斷，實務上應以高敏感度保護 |
| §8、§9 | 直接／間接蒐集的 **告知義務** | 手機連動取得行事曆、通知、聯絡人須告知 |
| §12 | 個資外洩時 **通知當事人**（2025 修法另加向個資會通報） | 事件應變程序 |
| §19、§20 | 非公務機關蒐集處理要件、特定目的外利用限制 | 用使用者資料訓練模型是否在原目的內？需同意或法定事由 |
| §21 | 國際傳輸可被主管機關限制 | 雲端推論服務設在國外 |
| §27 | 非公務機關 **安全維護措施** | 對應資安控制、42001 A.7 |
| §47、§48 | 罰則：違反安全維護義務等可處罰鍰，2023 修法後情節重大最高 1,500 萬元 | |

### 2.3 資通安全管理法（資安法）

| 項目 | 內容 |
|---|---|
| 沿革 | 2018 公布、2019 施行；**2025-09-24 修正公布**（施行日期由行政院定） |
| 主管機關 | 修正後為 **數位發展部**（由其指定資安專責機關執行，數發部資安署） |
| 適用對象 | **公務機關** 與 **特定非公務機關**（關鍵基礎設施提供者、公營事業、政府捐助之財團法人） |
| 核心義務 | 資通安全維護計畫、資安事件通報與應變、依責任等級辦理應辦事項、設資通安全長與專職人員、限制使用危害國家資安產品 |
| 罰則（修正後） | 特定非公務機關未通報資安事件最高 1,000 萬元；違反維護計畫等經限期未改正最高 500 萬元 |
| 稽核重點 | **先判斷是否適用**：一般消費性電子公司通常不是特定非公務機關，但若為政府供應商或 CI 供應鏈，可能受合約要求間接適用。法規清冊要寫清楚「適用／不適用與理由」 |

| 項目 | 內容 |

## 5. 稽核員怎麼看「法規」

- **稽核準則** 可以包含法規要求，但稽核員 **不是法官**：不判定組織「違法」，而是查組織 **有沒有識別、評估、處理** 適用法規，以及相關控制是否有效。
- 常查的證據：**法規遵循清冊**（法規名稱、適用條文、適用理由、負責人、對應控制、更新日期）、法規監控機制（誰追蹤修法、多久一次）、合規評估紀錄、管理審查是否討論法規變化。
- 常見發現：
  - 法規清冊沒有包含明顯適用的法律（例如處理健康資料卻沒列個資法 §6）
  - 修法後清冊沒更新（例如 2025 個資法、資安法修正、2026 AI 基本法施行）
  - 清冊有列，但沒有追溯到風險與控制（§4.2 → §6.1 斷鏈）
  - 「不適用」沒有理由
- 情境題原則：發現疑似違法 → 記錄客觀證據、依稽核準則判斷不符合、報告稽核組長；**不提供法律意見**。
