# 管理系統基礎：HLS、PDCA、過程導向、風險思維

> 對應課程單元 2、考試單元 1。自行整理。

## 1. 管理系統與管理系統標準（MSS）

- **管理系統**：組織為了達成目標，建立政策、目標與流程的一組相互關聯要素。
- **管理系統標準（MSS）**：規定管理系統要求的標準，例如 ISO 9001（品質）、ISO/IEC 27001（資安）、ISO/IEC 42001（AI）。
- **要求標準 vs 指引標準**：要求標準用「應（shall）」，可被驗證（42001、27001）；指引標準用「宜（should）」，不能拿來發證（23894、19011、42005）。

## 2. 高階結構（HLS / Harmonized Structure）

所有新版 ISO MSS 共用同一個 10 條款骨架，方便整合多套管理系統：

| 條款 | 主題 | PDCA |
|---|---|---|
| 1 | 範圍 | — |
| 2 | 引用標準 | — |
| 3 | 用語及定義 | — |
| 4 | 組織情境 | P |
| 5 | 領導作為 | P（貫穿全程） |
| 6 | 規劃 | P |
| 7 | 支援 | D |
| 8 | 運作 | D |
| 9 | 績效評估 | C |
| 10 | 改善 | A |

**42001 在 HLS 之上加了什麼（AI 特有）**
- §4.1 要考慮 AI 系統的預期目的、判定組織的 AI 角色
- §5.2 / A.2 的 **AI 政策**
- §6.1.2 **AI 風險評鑑**、§6.1.3 **AI 風險處理**（含 **適用性聲明 SoA**）、§6.1.4 **AI 系統衝擊評鑑**
- §8.2–8.4 執行上述評鑑與處理
- 附錄 A（規範性控制目標與控制措施，38 項）、附錄 B（實作指引）、附錄 C（AI 相關目標與風險來源）、附錄 D（跨領域使用）

## 3. PDCA

| | 意義 | 42001 例子 |
|---|---|---|
| Plan | 建立目標、找出風險與機會、規劃措施 | 組織情境、AI 政策、風險評鑑、AI 目標 |
| Do | 執行規劃 | 實施控制措施、運作管制、資源與能力 |
| Check | 監督量測，與政策、目標比較 | KPI、內部稽核、管理審查 |
| Act | 採取行動改善 | 矯正措施、持續改善 |

PDCA 同時作用在 **整個管理系統** 與 **每一個流程**。

## 4. 過程導向（process approach）

- 把活動當成 **相互關聯的流程** 管理：每個流程有輸入、活動、輸出、負責人、資源、量測、管制。
- 一個流程的輸出常是下一個流程的輸入 → 稽核要看 **介面**（交接點最容易出問題）。
- 稽核方法上：**沿流程追** 而不是只按條款逐條問（流程導向稽核）。

## 5. 風險導向思維（risk-based thinking）

- 預先識別可能影響目標達成的不確定性（風險與機會），用相稱的方式處理。
- 在 42001 有兩層：
  1. **管理系統層**（§6.1.1）：影響 AIMS 達成預期結果的風險與機會
  2. **AI 系統層**（§6.1.2–6.1.4）：AI 系統對組織、個人、群體、社會造成的風險與衝擊
- 風險管理過程（ISO 31000 / ISO/IEC 23894）：建立範圍與準則 → **風險評鑑**（識別 → 分析 → 評估）→ **風險處理** → 監督審查；全程溝通諮詢、紀錄報告。

### 常用風險詞彙

| 詞 | 白話 |
|---|---|
| 風險（risk） | 不確定性對目標的影響（可正可負） |
| 風險準則（risk criteria） | 判斷風險是否重大的參照標準 |
| 風險偏好（risk appetite） | 組織願意追求或保留的風險量與類型 |
| 風險等級（level of risk） | 後果 × 可能性的組合結果 |
| 風險處理選項 | 規避、承擔或增加風險以追求機會、移除風險源、改變可能性、改變後果、分擔、保留 |
| 殘餘風險（residual risk） | 處理後剩下的風險，需經權責人員接受 |
| 風險清冊（risk register） | 記錄已識別風險及其評估與處理的清單 |

## 6. AI 衝擊評鑑 vs 風險評鑑

| | AI 風險評鑑（§6.1.2） | AI 系統衝擊評鑑（§6.1.4，參考 ISO/IEC 42005） |
|---|---|---|
| 主要視角 | 對 **組織目標** 的影響 | 對 **個人、群體、社會** 的潛在後果 |
| 例子 | 模型失準造成召回、商譽損失 | 健康預警誤報造成使用者焦慮；特定族群準確度較差造成不公平 |
| 關係 | 衝擊評鑑結果是風險評鑑的輸入之一 | |

## 7. 文件化資訊（documented information）

- 標準要求「維持（maintain）」→ 指文件（程序、政策、範圍聲明）；要求「保存（retain）」→ 指紀錄（證據）。
- 42001 明確要求文件化的例子：AIMS 範圍、AI 政策、風險評鑑／處理過程與結果、SoA、衝擊評鑑結果、AI 目標、能力證據、運作所需文件、監督量測結果、內部稽核方案與結果、管理審查結果、不符合與矯正措施結果。
- 文件管制：識別、格式、審查核准、版本、發行、存取、保存與處置、外來文件。

## 8. 「建置」與「稽核」思維差異（單元 2 重點）

| 建置者 | 稽核員 |
|---|---|
| 想「要做什麼才符合」 | 想「有什麼 **客觀證據** 證明已符合且有效」 |
| 可以提出解法 | **不提供顧問建議**，只判斷符合與否 |
| 看自己寫的文件 | 抽樣查證文件、紀錄、訪談、觀察是否一致 |
| 文件寫完就好 | 文件要能追溯、被執行、被審查、被改善 |
