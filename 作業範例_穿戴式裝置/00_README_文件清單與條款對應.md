# 作業範例：穿戴式裝置公司 AIMS 組織治理文件

> 課程範例。公司名稱「智腕科技股份有限公司」為虛構，內容僅供學習 ISO/IEC 42001 條款 4 與 ISO/IEC 5338 Inception（6.4.1～6.4.3）之用。

## 1. 案例摘要

| 項目 | 內容 |
|---|---|
| 公司 | 智腕科技股份有限公司（虛構） |
| 產品 | AI 智慧手錶「WristAI」＋ 手機 App ＋ 雲端服務 |
| AI 預期目的 | 分析生理與行為資料，提供健康監測、運動分析、個人化建議及智慧語音助理 |
| AI 角色 | AI Developer、AI Provider |
| 關注重點 | ① 生理資料屬健康相關敏感資料 ② 手機連動可存取行事曆、通訊軟體通知、聯絡人、位置等隱私資訊 |

## 4. 「文件存在」vs「文件可作為稽核證據」

本範例刻意示範讓文件「可追溯、可驗證」的寫法：

| 只是文件存在 ❌ | 可作為稽核證據 ✅ | 本範例做法 |
|---|---|---|
| 「重視個資保護」 | 具體要求＋量測方式 | SR-05：通知內容僅在手機端處理，不上傳雲端；以封包擷取測試驗證 |
| 列出利害關係人名單 | 每個需求有編號且被下游引用 | IP-xxx → SN-xxx → SR-xxx 追溯鏈 |
| 「範圍：AI 相關業務」 | 明確的組織、系統、地點、資料、排除理由 | FRM-001-05 範圍聲明與排除表 |
| 空白核准欄 | 角色、日期、版本 | 每份文件均填寫核准紀錄 |
| 一次性填寫 | 有審查週期與觸發條件 | 年度審查＋重大變更觸發（法規、新增資料類別、新 AI 功能） |
